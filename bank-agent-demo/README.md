# سند: نموذج أولي لوكيل بنكي

نموذج عرض يعمل فعلياً لوكيل خدمة عملاء لبنك افتراضي اسمه «بنك الأمل»، على بيانات وهمية بالكامل.

الشاشة قسمان:
- **تطبيق العميل:** داخل إطار جوال، محادثة مع المساعد «سند»، وشاشة تأكيد من التطبيق تعرض البطاقة وتطلب رمز التحقق قبل أي إجراء.
- **لوحة مراقبة الوكيل:** مؤشرات (زمن الرد، وقرارات النموذج، واستدعاءات الأدوات، والرموز المستخدمة)، ومسار تنفيذ يعرض كل خطوة لحظة حدوثها: حاجز الإدخال، وقرار النموذج، والأداة ومدخلاتها ونتيجتها، وحاجز الإخراج، ثم بطاقات العميل وتذاكر الموظفين وسجل التدقيق.

> ⚠️ هذا نموذج عرض، وليس نظام إنتاج. لا يتصل بأي بنك حقيقي، ولا تُدخل فيه بيانات حقيقية.

## التشغيل

يحتاج Python 3.10 أو أحدث.

```bash
cd bank-agent-demo
python3 -m venv .venv
source .venv/bin/activate          # في Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.server:app --port 8000
```

ثم افتح `http://localhost:8000`.

## ثلاثة أوضاع للنموذج

تختار الوضع بالمتغير `LLM_PROVIDER` (انظر `.env.example`). الوكيل وأدواته وحواجزه لا تتغير بين الأوضاع.

| الوضع | متى تستخدمه | كيف |
|---|---|---|
| `scripted` · محاكاة بدون إنترنت | عرض مضمون بلا إنترنت ولا مفاتيح | الوضع الافتراضي عند غياب المفتاح |
| `anthropic` · Claude | عرض بنموذج حقيقي يفهم أي سؤال | `ANTHROPIC_API_KEY=... uvicorn app.server:app` (الرد خلال 4 إلى 6 ثوانٍ تقريباً) |
| `local` · نموذج مفتوح داخل البنك | الدول التي لا تخدمها واجهات النماذج التجارية، أو شرط بقاء البيانات داخل البنك | شغّل Ollama أو vLLM، ثم `LLM_PROVIDER=local LOCAL_MODEL=qwen2.5:14b uvicorn app.server:app` |

**عن وضع المحاكاة:** المسار كله حقيقي (الحواجز، والأدوات على البنك الوهمي، والتأكيد، والتذاكر، والسجل). الفرق الوحيد أن قرار «أي أداة أستدعي» وصياغة الرد يأتيان من قواعد ثابتة بدل نموذج لغوي، فهو يفهم أسئلة العرض وما يشبهها فقط. قل ذلك بوضوح إن عرضته أمام البنك.

**عن Claude:** واجهة Anthropic متاحة في دول محددة فقط: [القائمة الرسمية](https://www.anthropic.com/supported-countries). إن كان البنك في دولة غير مدعومة، فالمسار الصحيح هو الوضع المحلي.

**عن الوضع المحلي:** مثال بـ Ollama:
```bash
ollama pull qwen2.5:14b
LLM_PROVIDER=local LOCAL_BASE_URL=http://localhost:11434/v1 LOCAL_MODEL=qwen2.5:14b uvicorn app.server:app
```
جودة النماذج المحلية في العربية واستخدام الأدوات تختلف كثيراً. شغّل التقييم (بالأسفل) على أي نموذج قبل عرضه.

## لحظات العرض

الأزرار المرقمة أسفل المحادثة:

| # | السؤال | ما يُظهره |
|---|---|---|
| 1 | ليش انخصم مني 45 ريال أمس؟ | يفهم اللهجة، ولا يذكر مبلغاً إلا من نظام البنك |
| 2 | كم رسوم التحويل الدولي؟ | يجيب من وثيقة البنك ويذكر المصدر |
| 3 | أعطني آخر عمليات حساب أخوي | يرفض. لا توجد أداة تصل لحساب غير صاحب الجلسة |
| 4 | ضاعت بطاقتي اللي تنتهي 4821 | إجراء معلّق، ثم شاشة تأكيد من التطبيق ورمز تحقق (رمز التجربة `123456`) |
| 5 | كم صرفت على المطاعم هذا الشهر؟ | المجموع يحسبه الكود، لا النموذج |
| 6 | أبغى أكلم موظف | تذكرة للموظف مع ملخص، تظهر في اللوحة |

جرّب أيضاً كتابة رقم بطاقة كامل (16 رقماً) في رسالة: يظهر في اللوحة أن حاجز الإدخال أخفاه قبل وصوله للنموذج.

زر «إعادة العرض» يعيد البنك الوهمي لحالته الأولى.

**مستوى الجهد:** الافتراضي `EFFORT=low` لأنه أسرع أمام الحضور، ونجح في كل حالات التقييم مع Claude Opus 5 كما نجح `medium`.

## الاختبارات والتقييم

```bash
pytest -q                 # 16 اختباراً: الحواجز، والبنك، والأدوات، والمزوّدون الثلاثة، والخادم
python -m evals.run       # 15 حالة سلوك بالنموذج المحدد في LLM_PROVIDER
```

شغّل التقييم بعد أي تعديل في التعليمات (`prompts/`) أو تبديل النموذج. يخرج برمز 1 إن فشلت أي حالة.

آخر نتيجة مع Claude Opus 5: **15 من 15** بالجهد `low` و`medium`، والتعليمات الحالية `sanad-v2` (أضافت قاعدة كتابة التواريخ بكلمات مفهومة).

## البنية

```
app/
  server.py        الخادم: الجلسة، والبث (SSE)، ونقطة التأكيد، والحالة
  agent.py         حلقة الوكيل، تُصدر حدثاً لكل خطوة
  tools.py         الأدوات الست: الوصف الذي يراه النموذج، والتنفيذ الذي لا يراه
  guards.py        حاجز الإدخال (إخفاء الأرقام الطويلة) وحاجز الإخراج (مطابقة المبالغ)
  bank.py          البنك الوهمي: الحسابات والبطاقات والعمليات والإجراءات المعلّقة والتذاكر والتدقيق
  knowledge.py     البحث في الوثائق بعد توحيد الكتابة العربية
  providers/       Claude، والنموذج المحلي، والمحاكاة، خلف واجهة واحدة
prompts/           تعليمات الوكيل، لكل إصدار ملف (الحالي: sanad-v2)
knowledge/         وثائق البنك الوهمية (الرسوم، البطاقات، الاعتراض، التحويل)
static/            الواجهة (HTML وCSS وJavaScript بلا أدوات بناء، خط IBM Plex Sans Arabic)
evals/             حالات التقييم والمُقيِّم
tests/             الاختبارات
```

## قواعد ثابتة في الكود

- معرّف العميل يأتي من الجلسة، ولا يكون مُدخلاً في أي أداة.
- المبالغ أعداد صحيحة بالهللة.
- إيقاف البطاقة يُنشئ إجراءً معلّقاً، ولا يُنفَّذ إلا بعد تأكيد العميل برمز التحقق، ومرة واحدة فقط لكل طلب.
- كل مبلغ في رد الوكيل يجب أن يظهر في نتيجة أداة، وإلا يُحوَّل العميل لموظف.
- كل خطوة تُسجَّل.

## ما ينقصه قبل الإنتاج

الربط بأنظمة البنك الحقيقية عبر واجهاته المعتمدة، والتحقق الفعلي من الهوية ورمز التحقق، وبحث هجين حقيقي في وثائق البنك، وقاعدة بيانات بدل الذاكرة، ومراقبة وسجلات دائمة، ومراجعة أمنية واختبار اختراق، ومراجعة مهندس خبير لكل الكود.
